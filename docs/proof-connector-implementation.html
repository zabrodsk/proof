Proof across the website and chat hosts

One durable evidence service, with an OAuth-protected MCP interface and an authenticated browser report. The integration uses the same native jobs, source assets, extractions, provider adapters, and findings as the website.

Redacted public version. This record excludes credentials, account identifiers, private documents, repository locations, and deployment addresses. The implementation is local. Actual ChatGPT and Claude compatibility and public launch remain unverified.

What was built

Website / chat host→Shared application service→Native run + outbox→Worker + private sources→Stored findings + evidence

The MCP transport does not own the job. Disconnecting a client leaves the persisted job available through an authorized later request. Finished findings are read from storage rather than regenerated by the connector.

Verification and limits

Production TypeScript/Vite build passed. All 132 tests passed.

The integration regressions cover separate accounts, scoped source selection, extraction versions, idempotent retries and concurrent submissions, restart persistence, cancellation, revocation, deletion, fabricated evidence, strict inputs, actual PDF bytes and locators, and budget enforcement. Official SDK clients exercised the real Streamable HTTP route under two distinct platform grants. These are protocol tests, not actual ChatGPT or Claude app certification.

The paid Jev smoke test processed two claims against a controlled fictional source, returned stored evidence, and retained a negative finding for an unmeasured outcome. Reserved spend was approximately $0.001005; the provider's reported token-based estimate was approximately $0.000102. Billing was not independently confirmed. This proves the pipeline, not accuracy.

Database regressions ran the real schema in PGlite with pgvector. Ordinary PostgreSQL, S3 storage, pg-boss processes, production failover and worker restarts still require staging checks. No new deployment, directory listing, production OAuth client or host permission was created.

Run and configure

npm run db:migrate
npm run start
# Separate worker, same database, storage and provider settings:
npm run worker

npm test
npm run build
PROOF_INTEGRATION_LIVE=true npm run test:integration:live

Configure PostgreSQL with pgvector, private S3-compatible storage, browser account authentication, and provider secrets through the hosting secret manager. Enable PROOF_INTEGRATIONS_ENABLED for the browser connector API. Enable PROOF_MCP_ENABLED only after the OAuth authorization server and registered clients are ready.

OAuth configuration includes the exact issuer, remote JWKS URL, resource audience, introspection endpoint, allowed ChatGPT/Claude client IDs and the four named scopes. WorkOS browser sign-in does not itself provision WorkOS Connect. Authorization-code flow, S256 PKCE, consent and host callbacks must be configured at the established authorization server. Use the host's current callback values, not guessed addresses.

PROOF_OAUTH_AUTO_GRANT defaults to false. Enable it only if OAuth subject is the immutable ID of an existing signed-in account. Otherwise explicitly link the verified platform identity from the authenticated browser. Revoked links cannot silently reconnect. Source imports approved before disconnect may finish; unfinished checks are cancelled.

PROOF_CHECK_CREATION_ENABLED=false disables new checks/imports while reports remain readable. Maintain provider reservation prices against the real contract. Imports allow up to 12 MiB per file, eight items per request, 16 pending imports and 1,000 active source assets per workspace.

Submission copy for review

Proof checks explicitly selected writing against academic research or sources you choose. It returns saved claim findings, source passages and coverage limits. You can inspect the evidence in your authenticated Proof report. Proof does not automatically check every answer or silently edit your writing.

Task text and selected documents are processed by Proof and its configured research/assessment providers. Reports and uploaded files are private to the signed-in account. Platform access uses named scopes and explicit source selection; disconnecting removes that platform's access. Final privacy and retention statements require the deployed operator's approval.
