Findings

P1Existing gap retained in this task

1. Wrong-page citations can appear supported

src/studio-document.ts:143

In Check citations, selecting an uploaded source makes sourceCheckScope return selected_library. The engine skips its citation-correctness verdict in that mode.

Reproduction

Use a two-page source: page 1 discusses recruitment, page 2 supports the claim. Check “Exercise reduces depression (Brown 1).” with the UI scope helper.

{"support":"supported","citation":"not_checked","tone":"supported"}

The cited page does not support the statement, but its finding receives the supported UI tone. A citation proposal may separately offer a repair; that does not correct the misleading finding. The control run using citation-aware scope returns wrong_locator.

Required change. Use citation-aware scope in Check citations even when sources are selected. Keep source support and citation correctness separate in the result. Add a browser test that uploads a source and starts the check through the UI.

P1New batch endpoint retains an unsafe assumption

2. Verified fixes ignore a source’s changed eligibility

server/backend/citation-plans.ts:1176

applyVerifiedFixes checks document versions and the stored finding, but does not revalidate its source status, publication warning or evidence snapshot.

Reproduction

Create a verified numeric correction from 300 to 218 adults, then mark its source ineligible with publicationWarning=true before applying the batch.

The trial included 218 adults.

The edit is saved despite the source no longer qualifying as evidence. The test simulates the persisted state produced by the publication-status refresh; it does not call a live registry. research.ts:387 can make this change without invalidating an older run.

Required change. Revalidate every selected fix’s supporting source and exact evidence in the edit transaction. Reject stale fixes and request a fresh check. Share the relevant validation already used by citation-plan approval.

P2New classification defect

3. A factual qualification is discarded by the common-knowledge filter

shared/claims.ts:91

commonKnowledgeReason strips any final parenthesis before matching a familiar fact. That exemption is returned before the quantity and specialist checks.

Reproduction

Classify “Paris is the capital of France (its population doubled in 2024).”

common_knowledge

The unsupported population statement inherits the exemption of the familiar first clause. In a citation workflow this can suppress research and an uncited-gap warning for the whole sentence.

Required change. Remove only a recognized citation span, retain factual parentheticals, and evaluate all assertions before granting an exemption. Add a test that preserves a genuine citation while rejecting this qualification.

P2New exemption exposes lost quotation context

4. A sentence inside a quotation loses its citation requirement

shared/claims.ts:117

Sentence splitting removes the surrounding quote marks from the middle sentence of a multi-sentence quotation. The exemption check only recognizes paired marks within that individual sentence.

Reproduction

Classify: The textbook states, “The Sun is a star. The Earth is a planet. A week has seven days.”

“The Earth is a planet.” → common_knowledge

The middle sentence is part of the quotation but is marked citation-exempt. Passing paragraph context does not preserve its quote membership. The first and last fragments remain required, making the review internally inconsistent.

Required change. Track quotation spans in the original document and carry quote membership into each claim. Test multi-sentence and multi-line quotations, including a familiar fact in the middle.

P2New saved-plan defect

5. Partial approval loses the remaining uncited-gap record

server/backend/citation-plans.ts:1112

Approving one operation stores the whole plan as applied without recording selected operation IDs in its saved data or adding gaps for omitted citations. The applied UI then hides all proposal controls.

Reproduction

Generate two supported citation proposals; approve only the first; reload the saved citation plan.

{"status":"applied","operations":2,"gaps":0}

The saved document contains one cited claim and one uncited claim. The returned plan has zero gaps and no applied-operation list; the events table records the selection but the saved review does not use it. This misses the agreed requirement for explicit, durable coverage gaps.

Required change. Persist which operations were applied and retain a visible deferred or uncited status for the others. Rebase remaining proposals or explain that a new check is required. Test selective approval, reopen and export together.
