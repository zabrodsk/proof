Three clear modes.
One evidence workflow.

Check an existing document and its citations. Generate evidence-backed citations for a draft. Fact-check claims using public or academic sources. Each mode must produce an inspectable result and preserve the user's control over document changes.

Planning only. Code pointers, private classroom details, document links and task identifiers are omitted. The described changes have not shipped.

The three modes

1

Check citations

Input: text, bibliography and selected sources. References may be resolved externally only when the user permits it.

Work: find factual claims and evidence-based interpretations; connect existing citation occurrences to the right source and passage; inspect missing, misplaced and incorrect citations.

Output: a citation audit, exact passages and locators, bibliography issues, explicit gaps and safe proposed fixes. An uncited claim is still checked against the selected sources.

Do not search for new sources in this mode. If supplied evidence is missing, offer a deliberate switch to Generate citations.

2

Generate citations

Input: a draft, chosen citation profile and optional sources.

Work: review claims, use supplied evidence first, research remaining gaps, verify exact support and prepare in-text citations with matching bibliography entries.

Output: an approved version of the draft containing citations and Works Cited, plus a list of claims that could not be cited responsibly.

Citation insertion requires approval. Preserve the wording of the draft; any proposed factual correction is a separate, visible edit.

3

Fact-check

Input: text, optional selected sources and a visible All sources / Academic only choice.

Work: check each selected claim, find supporting and conflicting evidence, and report the scope and limitations of the search.

Output: supported, contradicted, overstated, partially supported or unverified findings with passages, source quality and safe correction proposals.

Fact-checking does not automatically insert a bibliography. Offer citation generation as an explicit next action.

All sources must mean a real public search. The current automatic academic/authoritative routing is narrower than this label. Add a public-source policy instead of renaming the existing policy. Academic only filters externally researched evidence to verified eligible academic sources; it must show a gap when no suitable source is available.

Scientific claims keep the existing academic evidence requirements in either scope. Uploads and selected sources retain their actual eligibility labels, so an ineligible source cannot silently pass an academic-only check.

A shared workflow that stays understandable

1. Set upChoose mode, source access, citation profile and document version.
2. Review claimsSelect, remove or add claims before any research starts.
3. Check evidenceInspect supplied sources, then research permitted gaps.
4. Review resultsRead findings, passages, locators and proposed edits.
5. Save & reopenApply approved edits once; verify the saved result and remaining gaps.

What counts as a claim

A statement that evidence can support or challenge, including an evidence-based interpretation. Preserve factual assertions even when they occur inside personal wording.

Skip standalone names, headings, titles, questions, instructions and pure preferences. Uncertain candidates remain selected by default so the app does not miss them. The preview shows why a candidate was included and lets the user correct the selection.

The browser and backend must agree on the exact span and surrounding paragraph. In-text citations, a bibliography and a title are structural information, not extra research claims.

What the UI should show

Keep the existing editor and evidence panel. Use the three action names consistently in onboarding, setup, progress and results. Display the source scope and citation profile beside the start action.

Show claim selection before starting; show processed claims, provider usage and unresolved work during the run. Report partial results honestly after a limit, cancellation or provider failure.

Group results into claims needing attention, proposed citation edits, and bibliography issues. Clicking an item highlights the exact draft span and opens the supporting or conflicting passage. Provide the same usable flow on mobile and with a keyboard.

Keep four judgments separate

JudgmentQuestion it answersExample
Claim supportDoes the inspected evidence support this precise statement?A real source supports a weaker result; the claim is overstated.
Citation correctnessDoes this citation identify the right work, location and statement?A claim is supported, but the citation points to the wrong page.
Source eligibilityDoes this source meet the selected policy?A preprint may be relevant but does not meet a verified peer-review requirement.
Processing completenessWas the permitted text inspected sufficiently?The abstract was available; the full article was not. Support remains unverified.

Correct formatting alone cannot turn an unsupported claim into a supported one. A second assessment must inspect the actual claim and evidence, not simply agree with the first model's answer. Conflicting passages and incomplete extraction remain visible and block automatic support-dependent fixes.

Citations, bibliography and one-click fixes

One citation formatter

Extend the existing pinned MLA/CSL formatter to produce both in-text citations and bibliography entries from the same normalized source records. Migrate the handwritten legacy and classroom formatters through adapters to prevent different screens producing different entries.

Start with Standard MLA 9 and a versioned classroom profile. Keep style overrides explicit and test them against verified examples. Do not add unrelated citation styles in this implementation.

Cover one, two and three-or-more authors; narrative citations; repeated authors; multiple works by one author; organizational authors; title-based citations; Unicode names; quotations; and page ranges. Missing metadata stays provisional. Never invent an author, page, volume, issue, access date or DOI.

Map every citation occurrence

Parse citation occurrences with stable offsets, citation form, locator and bibliography identity. Resolve candidates by verified identifiers and metadata, retaining ambiguity rather than guessing from a surname.

Bind the citation to the statement or clause it is meant to support. Catch wrong editions, wrong pages, citations attached to the wrong clause, uncited evidence-based claims, cited works missing from the bibliography, duplicate entries and unused entries.

Read the relevant text at the cited location. Preserve printed pagination separately from a PDF's file-page index. An accessible manuscript and the journal edition are different versions unless their pagination has been verified.

Store a citation edit plan before touching the draft

A plan contains the original document version, selected citation profile and its version, proposed text operations, source and reference identities, inspected evidence identities, locators and metadata fingerprints. The UI displays a before/after preview with each insertion linked to its evidence. Editing a source, profile, claim or document invalidates dependent proposals.

Unverified claims stay uncited and remain in the gap report. Do not add a plausible-looking citation to make a document appear complete.

Assignment profiles

Assignment rules are opt-in and separate from the general app. Store citation-count, source-count, locator, word-count and formatting requirements in a versioned profile. Count distinct works by verified identity, not only by DOI, so legitimate sources without a DOI are not excluded.

Report textual checks separately from things the app cannot establish, such as time spent editing or compliance with an external document's writing-history rules. Where an assignment requires writing in a designated document, use an audit and review workflow rather than suggesting that a generated replacement can be submitted.

Show the word-count convention and the observed count; keep the body, title and bibliography counts distinct. Do not manufacture text or citations to hit an assignment target.

Fewer API calls with the same evidence standard

Keep the current spending and request limits. Optimize redundant work, then measure calls, latency and coverage on the same fixtures. Reaching a limit produces a partial result with explicit gaps; it never lowers the criteria for a supported finding.

Reuse first

Inspect selected sources before searching. Reuse suitable verified evidence and source metadata across related claims. One fetched article can inform many findings; each finding still gets its own assessment of wording, numbers, negation, population and scope.

A cached passage from a paper does not prove that the rest of the paper contains no contradiction. Keep the full-source inspection state and extraction completeness alongside cached evidence.

Plan searches once

Group equivalent scoped queries, deduplicate equivalent sources by canonical identity and version, and coalesce concurrent requests. Search further only for insufficient support, a relevant contradiction, or missing provenance.

Make All sources use genuine public search with claim-appropriate ranking. Academic only uses eligible scholarly discovery and verified full text. An abstract, search snippet or citation count cannot substitute for inspected evidence.

Account for every attempt

Reserve budget for every physical provider request, retry and redirect. Attribute usage to the provider actually contacted. Bound concurrency and retries, honor rate-limit responses, and stop queued work when a run is cancelled or out of budget.

Strip credentials on cross-origin redirects and preserve correct redirect-method semantics. These protections must be tested before reusing provider responses.

Cache boundaries and invalidation

Query cache keys include normalized query, provider and parameters, language, source scope, freshness constraints and access boundary. Source records distinguish DOI/work identity from the exact full-text version and content fingerprint. Extraction, metadata, eligibility and assessed evidence have separate cache validity.

Keep private uploads and tenant-specific findings within their authorized workspace. Only publicly retrieved, policy-eligible data may use a public cache. A broader-scope result cannot pass an academic-only run by cache reuse. Revalidate changed source content, metadata, profile rules and relevant publication warnings.

Deduplicate only when equivalence is established. Do not remove URL parameters that identify an edition, page, authorized resource or document content. Coalesce in-flight identical requests without sharing private text between tenants.

Implementation order

Deliver in small, reviewable changes. Citation generation depends on both the citation model and the evidence/search policies, so it follows those foundations.

0

Establish the baseline

Start from current merged main in a clean branch and preserve unrelated local edits. Review the existing cloud provider patch before incorporating it. Capture the current three-mode UI, API contracts, failure behavior and provider-usage fixtures.

Exit A reproducible baseline, a reviewed provider change or explicit deferral, and a list of actual remaining gaps.

1

Shared citation model and mode setup

Add versioned citation profiles, occurrence parsing, source disambiguation and canonical in-text formatting. Add explicit public-source scope alongside existing policies. Rename the three UI actions and show their required inputs, claim preview, source access and output expectations.

Exit Shared contracts and migrations are compatible with older runs and connector submissions; profile and parser fixtures pass; changing a mode does not silently begin research or discard a draft.

2

Complete Check citations

Audit every citation occurrence and every selected claim needing evidence. Connect claim, occurrence, bibliography entry, source version and exact passage. Surface citation placement, locator, bibliography and eligibility failures independently. Add evidence-linked citation repair proposals.

Exit A supplied-source document yields correct findings and gaps with no unapproved discovery. The classroom profiles pass their verified fixtures.

3

Implement fact-check scopes and API efficiency

Implement public discovery and academic-only enforcement end to end. Add request coalescing, source-version reuse and scope-aware cache keys. Review double-checking on exact passages, late contradictions and incomplete full text. Finish retry, redirect, cancellation and budget accounting.

Exit The scope toggle changes real provider routing and evidence eligibility. Benchmarks show eliminated duplicate work without losing seeded conflicts or valid evidence.

4

Generate citations and apply one-click edits

Extend source discovery with a stored citation edit plan. Generate in-text and bibliography proposals only from verified evidence. Implement review, apply selected verified changes, atomic persistence, stale-plan rejection and idempotent retry. Add complete-document copy/download and reopen verification.

Exit A draft becomes one saved cited version after approval; unresolved claims stay explicit; retries cannot duplicate output and earlier versions remain intact.

5

Run the full acceptance sweep

Test document import, source ingestion, ownership, permissions, claim selection, three modes, evidence review, edits, persistence, copy/download and reopen. Exercise desktop and mobile, accessibility, connector compatibility, failures and live providers where credentials are available.

Exit A reviewable PR with a before/after usage report, screenshots, fixture artifacts and an honest distinction between mocked, live, untested and blocked checks.

End-to-end acceptance tests

Use a small, curated fixture corpus with known claims, exact passages, printed locators, expected metadata and deliberately broken citations. Keep provider recordings deterministic. Add limited live smoke runs for provider routing and real extraction; report them separately.

Evidence regression corpus

  • Support only in a later extracted section; contradiction still later.
  • Abstract appears supportive, full text narrows the population or conclusion.
  • Number, unit, negation, date or interpretation changes the claim.
  • Missing pages, OCR uncertainty, unreadable source or publication warning.
  • Author manuscript and published edition use different pagination.

Expected results must prevent a complete Supported label and automatic evidence-dependent fixes when uncertainty remains.

What the review should contain

  • Before/after screenshots for each mode on desktop and mobile.
  • A sample audited document and an approved cited output with exact expected passages.
  • Saved-version and reopen evidence, plus output comparison.
  • Per-provider usage and latency comparison on the same corpus.
  • Test results with live, mocked, skipped and blocked work distinguished.

Do not call the end-to-end work complete from unit tests or a mock-provider run alone.

Release gate

  • All three modes complete their defined journey and deliver the expected saved result or explicit gaps.
  • Canonical citation fixtures and evidence regressions pass; the selected profile is consistent across review, persistence and output.
  • Request deduplication is measured and supported findings do not regress.
  • Atomic edits, versioning, ownership, consent and connector compatibility pass.
  • Build, formatting, backend/integration tests and desktop/mobile browser checks pass for the final change.
  • Live provider checks have evidence, or the missing credentials/environment limitation is recorded as an unresolved release condition.

Recommended first implementation: establish the clean baseline, then build the shared citation profile and occurrence model with the three-mode setup.
