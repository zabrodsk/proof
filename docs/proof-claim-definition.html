The agreed claim boundary

  1. A claim is a factual assertion or an evidence-based interpretation that evidence could support or challenge.
  2. A bare name, header date, title, question, instruction or pure preference is excluded. A separate assertion inside personal framing remains eligible.
  3. Uncertain candidates stay selected by default. The writer reviews the preview, removes unwanted candidates and can include a skipped segment.
  4. Scientific assertions use academic research; public facts use supported authoritative domains. Literary and personal claims use relevant original or supplied material.

How a check runs

Save the version→Review claims→Assess supplied text→Research evidence gaps→Inspect and approve

Starting a check waits for autosave. Findings retain their original version and offsets. An approved correction changes its exact span; a stale correction is rejected. Reopening restores the saved text and review results.

A supported comparison with supplied text does not independently establish its provenance. Unknown judgment, incomplete extraction, abstract-only access, conflicting evidence and publication warnings do not suppress further research.

API efficiency with the same evidence standards

Reuse suitable work

Related claims share a search plan and candidate retrieval. Each receives its own evidence judgment. Completed candidate resolutions, including permanent exclusions, are reused within the run. Transient failures remain retryable.

Retrieve once

Academic verification obtains registry metadata before its strict eligibility and full-text checks. It no longer performs a preliminary duplicate Europe PMC retrieval. Bibliography resolution checks available local material before external registries.

Bound attempts

Retries observe caller deadlines, cancellation and bounded Retry-After delays. Every dispatched attempt and document redirect counts toward the existing request limits.

Keep accounting honest

Connector spending and native request admission share a transaction. A failed usage update cannot resend a successful paid request; its durable reservation remains visible with unknown usage.

The controlled related-claim case makes two Exa searches total, including the conflict search, for two opposite-direction claims. Their verdicts stay separate. A fully covered supplied-source case makes zero Exa searches and one Jev judgment.

Existing limits remain: 10 claims, 50 requests and 4 candidates for the small preset; 100 claims, 500 requests and 8 candidates for standard. Unchecked claims, inaccessible candidates and extraction gaps remain visible. No support threshold was lowered.

Scope and practical limits

This verifies the local app, its durable worker and the provider paths above. It does not certify a deployed production release, hosted sign-in, production object storage or every third-party document. No deployment or production migration was performed.

Academic checks inspect every extracted section permitted by the source selection. A later contradiction, uncertain section, incomplete extraction or interrupted judgment blocks complete support. A completed check still does not prove every figure or every possible outside source. Figures, equations, unreadable content, publication notices and unavailable full text still require explicit gaps or human review. A valid contradiction does not guarantee an automatic rewrite; safe correction gates remain in place.

Reproduce the automated acceptance with npm test, npm run test:e2e and npm run format:check. Run opt-in generated-text live acceptance with node --import tsx scripts/live-acceptance.ts and OCR acceptance with npm run test:firecrawl using configured providers.
